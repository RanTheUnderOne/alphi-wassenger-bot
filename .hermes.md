# Alfi Master Agent

This repository contains Alfi's business-agent skills and configuration.

## Skill loading

- The canonical project skill directory is `alphi-structure/skills/`.
- Each skill lives in its own directory and must have a `SKILL.md` with YAML frontmatter.
- Supporting material belongs under that skill's `references/`, `templates/`, `scripts/`, or `assets/` directory and must be referenced from `SKILL.md`.
- Load skills progressively: use the skill description first, then load the full `SKILL.md` only when the task matches it.
- `alphi-structure/crm/` contains the CRM capability contract and provider adapters; it is reference/configuration context, not a second skill root.

## Alfi operating rules

- Read `alphi-structure/SOUL.md` before making product or workflow decisions.
- Business workflows must use the CRM capability contract and must not hardcode Fireberry fields or tool names.
- Use the configured MCP servers in `alphi-structure/config.yaml`; never invent a provider or account alias.
- Never send customer-facing messages or mutate CRM data without the approval required by the SOUL and the active tenant policy.
- When a skill says it is only a design/reference document, do not present it as an implemented runtime capability.

## Project language

- Configuration and skill instructions are written in English.
- Owner-facing reports and CRM notes are written in natural, concise Hebrew.
- Keep responses action-oriented and state uncertainty explicitly.

## Current structure

- `alphi-structure/SOUL.md` — role, voice, guardrails.
- `alphi-structure/config.yaml` — intended MCP configuration.
- `alphi-structure/ENVIRONMENT.md` — required environment variables.
- `alphi-structure/skills/` — source skills, business skills, and Wassenger skills.
- `alphi-structure/crm/` — CRM abstraction and adapters.
- `alphi-structure/cron/` — routine documentation.

This file is project context for Hermes-compatible agents. It does not replace the runtime Hermes profile configuration.
